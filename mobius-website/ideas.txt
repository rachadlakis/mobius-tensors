AI Agents 

5 Python Frameworks




	
Infographic by Dr. Maryam Miradi comparing 5 AI Agent frameworks — LangGraph, CrewAI, PydanticAI, OpenAI Swarm, and MCP — with use cases, best scenarios, and a decision matrix to help AI builders pick the right tool.



	
I've taught AI Agents to 2,300+ engineers. 
The framework debate wastes more time than anything else.

Picking the wrong AI Agent framework won't kill your project. Debating it for weeks will.

LangGraph, CrewAI, PydanticAI, Swarm, and MCP are not competitors. 
They are Python libraries, each with different depth, different abstractions, and different strengths.

You don't debate NumPy vs Pandas. You ask what you're building. Same rule applies here.

LangGraph
- Stateful pipelines, loops, branching, production-grade, full control
- Use it when failure is not an option

CrewAI
- Multi-agent teams, role-based, readable code, fast to ship
- Use it when the problem needs a team, not a tool

PydanticAI
- Structured outputs, type-safe, validation-first, native Python feel
- Use it when bad data is not an option

OpenAI Swarm
- Minimal abstraction, agent internals exposed, best for learning
- Use it when you want to understand, not just ship

MCP (Model Context Protocol)
- Connects agents to real-world tools, works across every framework above
- Use it when your agent needs to reach beyond itself

Fraud detection, medical pipelines, compliance systems, research agents each one maps to a different framework.

The right library depends entirely on what you are building not on what is trending.

What are you building? and which framework did you reach for first?

17 Types of RAG




	
Infographic by Dr. Maryam Miradi mapping all 17 types of RAG across four categories — Core Paradigms, Retrieval Strategy, Self-Improving, and Data Type — plus Agentic RAG and a guide to 6 vector databases, each linked to its arXiv paper.



	
The simplest RAG retrieves from a database. 
Flavour it with Agents, Graphs, Cache or Hierarchy in 17 Ways.

Core Paradigms
the foundation every engineer starts with.

1. Naive RAG: basic retrieve and generate pipeline. 
2. Advanced RAG: pre and post retrieval optimization. 
3. Modular RAG: composable, swappable retrieval modules. 

Retrieval Strategy
how and what you retrieve.

4. Hybrid RAG: dense and sparse retrieval combined. 
5. Fusion RAG: multiple queries fused before retrieval. 
6. HyDE RAG: hypothetical document embeddings for retrieval. 
7. Hierarchical RAG: multi-level chunking and retrieval. 
8. Adaptive RAG: adapts retrieval strategy to query complexity. 

Self-Improving: 
RAG that detects and fixes its own mistakes.

9. Self-RAG: model reflects and critiques its own outputs. 
10. Corrective RAG: detects bad retrievals and self-corrects. 
11. Speculative RAG: draft answer first, verify with retrieval after. 
12. Recursive RAG: retrieves and refines iteratively until complete. 

Data Type: 
what your retrieval source actually looks like.

13. Graph RAG: knowledge graphs instead of vector search. 
14. Multimodal RAG: images, audio, video as retrieval context. 
15. Structured RAG: retrieves from tables and databases, not just text. 
16. Contextual RAG: compresses and enriches context before generation. 

Agentic RAG: 
agents dynamically control the entire retrieval loop.

17. Agentic RAG: the most powerful paradigm. Also the most misunderstood. 

+ 6 Vector Databses for RAG:
- Weaviate: open source, built-in vectorization, production ready. 
- Milvus: open source, built for billion-scale vector search. 
- Qdrant: open source, Rust-based, fast and memory efficient. 
- FAISS: Meta's library for efficient similarity search. 
- Pinecone: managed cloud, zero infrastructure, production grade. 

The database is just the starting point. 
What you add on top is where the real engineering begins.
